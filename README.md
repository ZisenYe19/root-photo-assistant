# 根 Root · 手机摄影辅助工具

> 从照片读回光线，翻译成拍摄动作。

一张普通模式拍下的照片 → 分析现场光线 → 给出专业模式的拍摄参数 → 拍完一键出片，同时输出 Lightroom 参数供 RAW 精修。

**在线体验**：`<GitHub Pages 链接>` ｜ **安卓安装包**：[`软件成品/app-debug.apk`](软件成品/app-debug.apk)

---

## 一、为什么做这个

手机用户和专业模式的矛盾在于：普通模式随手一拍就有可用的照片，而专业模式（Pro / 手动）能拍出更好的画质，却要求使用者自己判断现场光线并给出 ISO、快门、曝光补偿、白平衡、对焦模式。参数判断依赖经验，新手打开专业模式往往只能乱拨滑块。

根 Root 把这套判断自动化：**用一张普通模式照片当作测光表**，把现场光线量化成数字，再按拍摄意图翻译成一组可以直接照着拨的参数。

目标用户是 vivo 手机用户与摄影爱好者，同样适用于任何支持专业/手动模式的手机。

## 二、核心功能

**1. 光线分析（理解现场）**

| 指标 | 含义 |
|---|---|
| 平均亮度 L（0–255） | 整张照片有多亮，参数计算的基准量 |
| 亮度直方图（256 级） | 阴影/高光有没有丢，用文字给出可执行结论 |
| 平均 R / G / B | 偏色方向 |
| 估算色温（K） | 现场光源偏暖还是偏冷 |
| 标准差 stdDev | 对比度高低 |
| 饱和度 | 色彩浓度 |

直方图不是画着好看：它直接翻译成人话，例如"高光溢出，建议降低 EV"、"暗部丢失，建议提高 EV"。

> 实测（Chromium + 两张测试图）：
> - 逆光图（亮度 128.3 / 色温 4961K）→ 逆光预设给出 `EV +1.4 · ISO 100 · 1/30 · 5100K · 点测光`；
> - 暗光图（亮度 43.9）→ 同一个预设给出 `EV +1.0 · ISO 300 · 1/30 · 5600K · 自动`，直方图提示"暗部丢失，建议 +EV"。
>
> 同一个预设、两张照片、两组不同参数，这就是"动态"的实际含义。

**2. 场景预设与动态参数**

内置 4 个预设，全部对应真实的拍摄意图：

| 预设 | 意图 | EV 方向 | 测光/对焦 |
|---|---|---|---|
| 逆光 | 主体背光偏暗，提亮主体防"黑脸" | 正向 | 点测光 · 中央重点 |
| 剪影 | 故意让主体欠曝成轮廓，保住亮背景 | 负向 | 点测光 · 高光 |
| 暗环境 | 照度低，提亮同时控噪 | 轻微正向 | 自动/手动，允许升 ISO |
| 高亮 | 强光/雪景/沙滩，防过曝 | 负向 | 点测光 · 高光，ISO 压到最低 |

**关键点：所有参数随照片动态计算，没有一个是写死的。** 同一个"逆光"预设，对着不同亮度的照片给出的 EV、ISO、快门、白平衡都不同——计算规则见第四节。

**3. 自定义预设**

上传一张参考图 → 提取它的光线风格 → 保存为预设 → 之后可以复用、改名、删除。选自定义预设时，工具以"拍出接近参考图的效果"为目标给出参数，后期也用差值法把当前照片往参考图靠。

**4. 一键出片 + Lightroom 参数**

- **两个独立槽位**：上方「上传现场照片」是光线参考（负责测光与拍摄参数，全程保留），「后期与导出」里另有一个「专业模式拍摄的成片」槽（负责后期与 Lightroom 导出）。按参数实拍回来后放进成片槽即可，不必把参考照片换掉、分析数据也不会丢；
- **后期强度滑块（默认 30%）**：控制"场景补偿"的作用力度，0% 只保留预设自身风格、100% 为完整补偿。拖动实时重算，30% 时可随时加码到 100% 或回退到 0% 对比，同一个预设能覆盖从"轻微修饰"到"强力改造"的范围；
- 网页内直接完成 JPEG 后期（色温 → 亮度 → 对比度 → 饱和度），可暂存、对比、下载；
- 同时输出一份 Lightroom 参数清单（曝光度/对比度/高光/阴影/白色色阶/黑色色阶/色温/色调/饱和度/噪点消除），供 PC 端 RAW 精修直接照抄。

**RAW 的定位**：专业模式可以同时拍 RAW + JPEG，本工具只处理 JPEG，RAW 留给 Lightroom——网页端不做 RAW 解码，这是刻意的取舍，不是能力缺口。

**5. 全程本地**

零依赖、零后端、零 CDN，单个 HTML 文件双击即用。照片不上传任何服务器，断网可用。

## 三、怎么用

**拍前（获取参数）**
1. 用普通模式随手拍一张现场照片，放到**「上传现场照片」**槽（这张只负责测光，之后一直留着）；
2. 读分析结果（亮度、直方图解读、估算色温），在**「① 预设与参数」**里选择拍摄意图（逆光 / 剪影 / 暗环境 / 高亮，或自定义预设）；
3. 照着"专业模式建议参数"表，在手机专业模式里拨到对应数值拍摄。

**拍后（出片与精修）**
4. 切到**「② 后期与导出」**，把刚拍的成片放到**「第二步｜专业模式拍的成片」**槽——这是独立的第二个位置，**不会覆盖步骤 1 的参考照片**，上方的光线分析与拍摄参数始终保留，方便反复对照重拍；
5. 点"一键优化"，力度不合适就拖"后期强度"滑块，满意则"暂存"，最后一起保存（APK 内直接存入系统相册）；
6. 需要极限画质时，按"Lightroom 参数"清单在 PC 端精修 RAW。

> 两个槽位的关系：**参考照片负责"拍之前"，成片负责"拍之后"**。成片的后期参数按成片自己的实际亮度计算，而拍摄参数始终基于参考照片——所以你可以按同一组参数重拍多张，逐个丢进成片槽优化比较。没有上传独立成片时，一键优化仍作用于参考照片（旧行为保留，单个槽位也能用）。更换参考照片会清空成片槽与已有结果，避免张冠李戴。

**三种使用方式**
- 安卓：安装 `软件成品/app-debug.apk`（安装时需要允许"未知来源"）；
- 手机/电脑浏览器：直接打开 `index.html`；
- 部署：把 `index.html` 放到任意静态服务器或 GitHub Pages 即可。

> 自定义预设保存在手机本地（localStorage 存风格数据 + IndexedDB 存参考图原图），换设备不会同步。可用"重置"重新读取本地存储。

## 四、算法说明

代码不复杂，但每个数字都有来源。

**1. 图像分析**

采样到最大边 200px 后读取像素，亮度用 Rec.709 感知亮度：

```
L = 0.2126·R + 0.7152·G + 0.0722·B
```

同时统计平均 R/G/B、标准差、饱和度、256 级直方图，并统计最暗端（<15）与最亮端（>240）的像素占比，用于直方图解读。

**2. 动态参数计算**

以目标亮度 `targetL`（每个预设不同，自定义预设取参考图的 L）与实际亮度 L 的偏差为核心：

```
dEv      = (L - targetL) / 25                     // 每 25 级亮度折合约 1EV 偏差
快门      = SHUTTER_LIST[clamp(baseShutterIndex - round(dEv), 0, 14)]
EV       = evOffset - dEv * 0.5                   // 预设意图 + 现场偏差修正
ISO      = baseISO 按 isoMode 与现场亮度微调（暗了升、极亮减半，有上限保护）
白平衡    = 现场色温 × 0.6 + 预设目标色温 × 0.4
对焦模式   = 依偏差大小在"自动"与"点测光"之间切换
```

ISO 的 `isoMode` 是必要的：剪影和高亮场景的语义是"故意欠曝/防过曝"，绝不能被一张暗照片把 ISO 拉高。

**3. 自定义预设（差值法，不套死值）**

```
拍摄：dEv = (当前 L - 参考图 L) / 25，其余同上
后期：brightness = clamp(参考图 L - 当前 L, -80, 80)
      contrast   = (参考图 stdDev - 当前 stdDev) × 10
      saturation = (参考图饱和度 - 当前饱和度) × 100
      色温       = 按 R/B 通道比例修正
```

**4. 后期处理**

内置预设的后期参数拆成两层相加，这是为了不让"场景补偿"失控：

```
后期参数 = 预设风格层 (post.brightness / contrast / saturation)
         + 场景补偿层 × 后期强度
场景补偿层 = clamp(round((targetL - L) * 0.6), -60, 60)
```

风格层是预设的固有倾向（强度恒为 100%），补偿层才是随照片变化的动态部分，由"后期强度"滑块按 0–100% 缩放。举例：一张 L=64 的宿舍照选"逆光"，补偿层算得 +52，强度 30% 时亮度只加 `25 + 16 = 41`（旧公式是直接相加得到 +77，会把整幅画面抬到 139、高光压成一片白）；把滑块推到 100% 就能拿回完整的补偿力度。

`applyPost` 按顺序作用于每个像素：色温（R/B 通道系数）→ 亮度加值 → 对比度（标准 S 曲线因子 `(259(c+255))/(255(259-c))`）→ 饱和度 → 每步 clamp 到 0–255。

**5. Lightroom 参数**

```
色温   = 预设目标 × 0.7 + 现场实测 × 0.3
对比度  = 预设值 + (45 - stdDev) × 0.5
阴影   = 预设值 + (targetL - L) × 0.5
曝光度  = 预设值 + (targetL - L) / 50
```

照片越偏离预设目标，后期补正越大；越接近，参数越接近预设基准值。

## 五、实现中遇到的问题与解决

这一节是项目里真正的技术内容——每个问题都是实际动手时撞上的，不是设想出来的。

**1. 参数"看着动态，其实是死的"**
最初每个预设的 EV/ISO/白平衡都是固定值。测试同一个预设对着亮度 40 和亮度 200 的照片，给出的参数完全一样，等于没分析。改为先把光照偏差 `dEv` 算出来，所有参数再由 `dEv` 推导，预设只提供"意图方向"（evOffset、targetL），不提供"死值"。

**2. 色温被现场值覆盖**
后期色温原本直接取现场估算色温，导致自定义预设的色温风格被冲掉（参考图是暖调、现场是冷光，结果给出冷调）。改成加权融合：预设目标 0.7 + 现场实测 0.3，既保留风格，又保留现场的合理性。

**3. 色温精度**
`色温 ≈ 5500 - (avgR - avgB)/255 × 4000` 是工程近似，与实际色温误差约 ±1000K。**知道不准还要用，是因为它服务的目标不是精确白平衡，而是"暖/冷"这个二值判断**——知道现场偏冷还是偏暖，比知道具体 4300K 还是 5300K 更有用。误差在 UI 和 README 中明确标注，不假装精确。（要提高到可用精度需要灰点白平衡 + CCT 查表，属后续方向。）

**4. 手机浏览器存不下参考图**
自定义预设最初把参考图转成 dataURL 存 localStorage，几百 KB 的图到第三张就报 `QuotaExceededError`。改为三层存储：localStorage 只存 8 个数值字段 + 降级缩略图；参考图原图以 Blob 存进 IndexedDB（浏览器内置、无容量焦虑、可存二进制）；本次会话展示用 ObjectURL。删除预设时三处同步清理（元数据 + IndexedDB 原图 + revoke ObjectURL），避免内存泄漏。IndexedDB 不可用（隐私模式等）时自动降级到缩略图方案，功能不中断。

**5. 保存预设卡按钮**
早期版本读参考图时对原图做全尺寸解码再统计，手机上一张 5000×4000 的照片要等数秒，用户以为卡死会连点。改为 `createImageBitmap(file, {resizeWidth: 240})` 让浏览器在解码阶段就缩放，统计只用 240px 小图（毫秒级），原图仅做存储。并加了防双击 + 20 秒解冻兜底，任何异常路径都会恢复按钮。

**6. 批量下载被手机浏览器拦截**
暂存区连续触发多次 `a.click()`，手机浏览器会以"多文件下载"为由拦截。改为每次下载间隔 500ms，并在界面明示"开始下载 N 张"，让用户知道预期行为（zip 打包是后续优化方向）。

**7. 直方图解读要说人话**
只画直方图，用户看不懂。加了文字结论层：高光像素占比 >5% → 建议降 EV；暗部 >5% → 建议提 EV；stdDev >70 → 高对比；<25 → 低对比。阈值是先验经验值，需要真机拍照继续校准。

**8. 真机反馈："点了保存，怎么弹出分享面板？"**
第一次装到手机上点导出，弹出来的是系统分享面板（抖音 / 朋友圈 / 微信状态 / 打印 / 网页传 / 隐私打码），里面**没有"保存到相册"**。原因不是功能坏了，而是文件位置不对：`Filesystem.writeFile({ directory: Directory.Cache })` 把成片写在应用私有缓存目录，再通过 FileProvider 临时授权给分享面板——相册应用不接受这种临时文件，系统自然不会给出"保存到相册"这个目标。Capacitor 官方 Filesystem 插件也补不了这个洞：`Directory.ExternalStorage` 只在 Android 9 及更早可用，`Directory.Documents` 在 Android 11+ 只能访问本应用创建的文件，两者都写不进系统相册。
正解是走 MediaStore：引入 `@capacitor-community/media`（peer 依赖 `@capacitor/core >= 8.0.0`，正好对应本项目的 Capacitor 8），它把文件写进 `Pictures` 下本应用的相册目录并调用 `scanPhoto()` 登记，相册立刻可见，而且**保存到自己的相册不需要任何存储权限**。
实现时读了一遍插件的 Java 源码，避开两个坑：`albumIdentifier` 在原生侧是必填（缺了直接 reject，不是可选项），所以必须先 `createAlbum()` 再 `getAlbums()` 取到目录路径；`blob:` 协议原生端读不到，必须转成 data URL 传过去（插件原生实现专门支持 `data:` 前缀）。

## 六、技术要点

全部能力来自浏览器标准 API，**零第三方运行时依赖**：

- **像素计算**：Canvas 2D `getImageData` / `putImageData`，逐像素做亮度、统计与后期；
- **智能缩放**：分析用 200px 小图（保证速度），后期用最大边 3000px（保证出片画质），两者共用同一套统计函数；
- **存储**：`localStorage`（小数据）+ `IndexedDB`（Blob 原图）+ `ObjectURL`（会话内展示），三层各司其职，删除时同步清理；
- **性能与稳定性**：`createImageBitmap` 解码期缩放、`willReadFrequently: true` 避免画布回读惩罚、异步按钮防卡死、IndexedDB 不可用时自动降级；
- **打包**：Vite 相对路径构建（`file://` 与 WebView 通用）+ Capacitor 安卓壳，GitHub Actions 一键出 APK。

## 七、已知边界

诚实地写清楚工具的能力范围：

- 参数为**起手参数**，不是精确测光表。真实拍摄受镜头、测光模式、机内算法影响，建议拍一张回放确认后微调；
- 色温为工程估算，**误差约 ±1000K**，只适合判断冷暖倾向；
- 只处理 JPEG，网页端不解码 RAW（RAW 交给 Lightroom）；
- 光线分析为**全局平均 + 直方图**，不做局部点选测光。逆光场景下主体偏暗、背景极亮时，全局平均值会把现场亮度估高，这时的参数应以预设意图（提亮主体）为主，本工具已按此设计参数方向；
- 一次处理一张照片，不做批量；
- 直方图解读阈值、ISO 上下限为经验值，需真机校准；
- 自定义预设存在本机，不跨设备同步、无云端。

## 八、项目结构

```
root/
├── index.html                 # 全部界面 + 算法，单文件；直接双击即可用，无需构建
├── src/bridge.js              # 安卓壳的保存能力：写入系统相册（MediaStore）
├── package.json               # 依赖与构建脚本；@capacitor-community/media 用于存相册
├── vite.config.js             # base: './' + 两个入口（页面与 bridge），适配 file:// 与 WebView
├── capacitor.config.json      # Capacitor 安卓壳配置
├── .github/workflows/build-apk.yml   # 推 tag 或手动触发时自动构建 APK 并上传产物
├── index.html.html            # 第一版（未重构、未拆模块），保留作演进对照
└── 软件成品/
    ├── app-debug.apk          # 安卓安装包
    └── gen.zip                # 提交材料打包
```

**构建与打包**（Node 20+）

```bash
npm install

# 网页产物：www/index.html（源码原样拷贝，双击可用）与 dist/（含 bridge 打包产物）
# 部署到静态服务器 / GitHub Pages 用 dist/；只想在手机上直接打开用 www/index.html
npm run build:web

# 安卓 APK（需要 JDK 17+ 与 Android SDK；不装也行，仓库里已有构建好的 APK）
npx cap add android
npx cap sync android
cd android && ./gradlew assembleDebug     # Windows: gradlew.bat assembleDebug
```

> 网页版（`index.html`）不依赖任何构建：算法、界面、样式全在这一个文件里。`bridge.js` 只在 APK 内起作用，浏览器中未加载也不影响任何功能。
>
> APK 内那个按钮叫"保存到相册"：成片写入系统相册的 `Pictures/Root/` 相册（MediaStore 登记，相册应用立即可见），无需任何存储权限。发微信、发抖音等从相册里选即可。
>
> 保存有两条路：检测到 `window.__nativeSave`（bridge.js 在 APK 内注册成功）就走原生写相册；否则一律退回浏览器的 `a.click()` 下载。原生保存失败时会提示"保存到相册失败，改用下载"并自动退回，不会出现点了没反应的情况。`filesystem` 与 `share` 两个依赖仍保留：它们是早期版本的导出方式，删除会与已经生成过的 `android/` 工程不一致，留到下次重建原生工程时一起清。

## 九、后续方向（按优先级）

1. `下载全部` 改为 zip 单包下载，彻底绕开浏览器的多文件拦截；
2. 读取 EXIF（ISO / 快门 / 光圈），用机内实际参数校准估算值，给出更贴近的起手参数；
3. 色温改用灰点白平衡 + CCT 查表，把 ±1000K 压到 ±200K 量级；
4. 真机拍摄样本库：同一场景拍一组样片，回填校准直方图阈值与 ISO 上下限。
