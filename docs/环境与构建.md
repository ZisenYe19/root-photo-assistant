# 运行环境与构建说明

本文档说明两件事：**怎么运行这个项目**（不需要开发环境），以及**怎么从零构建安卓 APK**（需要开发环境）。

---

## 一、运行环境（使用者）

### 方式 1：安卓手机（推荐）

| 项 | 要求 |
|---|---|
| 系统 | Android 7.0 (API 24) 及以上 |
| 权限 | **无需任何存储权限**（保存到相册通过 MediaStore 写入本应用相册） |
| 安装 | 允许"未知来源"后安装 `apk/根Root-摄影辅助工具.apk` |
| 网络 | **完全离线可用**，照片不上传、不联网 |

**注意**：APK 使用 Debug 签名，包名为 `com.example.root`。若手机中已安装其他使用 `com.example.*` 包名的调试应用，会提示"应用未安装"，需先卸载冲突应用。

### 方式 2：浏览器（零安装）

直接用浏览器打开 `index.html` 即可，手机与电脑均可。

| 浏览器 | 支持情况 |
|---|---|
| Chrome / Edge / 三星浏览器等 Chromium 内核 | ✅ 完整支持 |
| Safari (iOS/macOS) | ✅ 支持 |
| Firefox | ✅ 支持（界面中的 `backdrop-filter` 等装饰效果可能略有差异，不影响功能） |

**支持的输入格式**：JPEG / PNG / WebP / HEIC 等手机相册常见格式（由浏览器解码能力决定）。

**存储说明**：自定义预设保存在本机浏览器中——`localStorage` 存风格数值（上限约 5 MB），`IndexedDB` 存参考图原图。清除浏览器数据会一并清除预设。

## 二、开发与构建环境（开发者）

### 本项目实际使用的版本

以下版本是**实测构建成功**的组合，建议照抄，避免版本组合问题：

| 组件 | 版本 | 说明 |
|---|---|---|
| Node.js | **20 或以上**（本项目用 24.19.0 验证） | 跑 Vite 构建 |
| npm | 10 或以上（本项目用 11.17.0） | |
| JDK | **21**（OpenJDK 21.0.2） | Capacitor 8 要求 Java 21 |
| Android SDK Platform | **android-36** | `compileSdk = 36` |
| Android SDK Build-Tools | **35.0.0** | AGP 8.13 默认需要此版本（装 36.0.0 也不认） |
| Android SDK Platform-Tools | 37.0.1 | Gradle 会自动补装 |
| Gradle | **8.14.3** | 由 `gradlew` 自动下载 |
| Android Gradle Plugin | 8.13.0 | 由 Capacitor 模板指定 |
| Capacitor | 8.x | 见 `package.json` |

> **为什么 Build-Tools 要 35.0.0 而不是最新的**：虽然 `compileSdk` 是 36，但 AGP 8.13 的默认 build-tools 版本是 35.0.0，缺失时 Gradle 会直接报 `Failed to install the following Android SDK packages`。装 36.0.0 不能替代。

### 从零构建 APK

```bash
# 1. 安装依赖
npm install

# 2. 构建网页产物（输出到 dist/）
npm run build:web

# 3. 生成安卓原生工程（首次需要）
npx cap add android

# 4. 同步网页产物与插件到原生工程
npx cap sync android

# 5. 构建 Debug APK
cd android
./gradlew assembleDebug          # Windows: gradlew.bat assembleDebug
```

产物位置：`android/app/build/outputs/apk/debug/app-debug.apk`

**注意**：`app-debug.apk` 是 Debug 签名，可直接安装但**不适合上架应用商店**。需要发布版请自行配置签名后执行 `assembleRelease`。

### 环境变量

构建前需设置（Windows 示例）：

```powershell
$env:JAVA_HOME       = "<JDK 21 目录>"
$env:ANDROID_HOME    = "<Android SDK 目录>"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:Path = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\cmdline-tools\latest\bin;$env:Path"
```

### 网络受限环境下的构建

在国内网络直连 `dl.google.com`、`services.gradle.org`、`repo1.maven.org` 很容易超时或证书失败。本项目提供了 `gradle-mirror.init.gradle`，把依赖仓库换成国内镜像：

```bash
cd android
./gradlew assembleDebug --init-script ../gradle-mirror.init.gradle
```

Gradle 发行版本身若下载失败，可修改 `android/gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl` 指向镜像，例如：

```
distributionUrl=https\://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-bin.zip
```

### 常见构建问题

| 现象 | 原因与解决 |
|---|---|
| `Your project path contains non-ASCII characters` | 工程路径含中文，AGP 8.13 会直接拒绝。**把工程移到纯英文路径**（不要用 `android.overridePathCheck=true` 绕过，那只是关掉警告，下游工具仍可能失败） |
| `Failed to install ... build-tools;35.0.0` | 缺 build-tools 35.0.0，见上表 |
| `Could not resolve project :capacitor-android`（No variants exist） | `capacitor.settings.gradle` 中的相对路径 `../node_modules/` 解析基准不符预期。可把该文件里的 `projectDir` 改为绝对路径 |
| Gradle wrapper 报 `PKIX path building failed` | 下载 Gradle 发行版时证书验证失败，改用国内镜像的 `distributionUrl` |
| 打出来的 APK 里是旧界面 | 忘了把新的 `dist/` 同步进构建目录。改完代码务必重新执行 `npm run build:web` |

### 构建耗时参考

| 步骤 | 耗时 |
|---|---|
| `npm install` | 约 15 秒 |
| `npm run build:web` | 约 0.2 秒 |
| 首次 `gradlew assembleDebug`（含下载 Gradle 发行版与依赖） | 约 1～3 分钟 |
| 增量 `gradlew assembleDebug`（仅改了网页产物） | 约 10 秒 |

## 三、自检脚本

```bash
node diag-check.js          # 校验 index.html：JS 语法、$(id) 引用、CSS 类是否都能对上 DOM
node check-workflow.js      # 校验 GitHub Actions 工作流与引用文件是否都已纳入 git
```

`diag-check.js` 在改动界面后尤其有用——它能发现"引用了不存在的元素"这类改样式最容易犯的错。
